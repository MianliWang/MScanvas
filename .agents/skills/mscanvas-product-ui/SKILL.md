# MSCanvas product UI

1. Start from user jobs and accepted workflow structure, not a dashboard template.
2. Preserve the main scientific evidence area and familiar desktop selection/focus behavior.
3. Design at 1366×768 first, then 1920×1080 and 960×640 constrained state.
4. Make high-frequency actions discoverable; high-risk actions explicit and recoverable.
5. Include empty, loading, progressive, unsupported, failure, selected, keyboard-focus and active-run states.
6. Use semantic tokens and project-owned component families. Generic design skills are advisory only.
7. Glass, bento, hover, cards and dense tables are permitted when task fit, accessibility and prototype evidence justify them.
8. Essential information must have a visible/focusable/pinnable path even when hover accelerates inspection.
9. Do not add dead future navigation or analysis surfaces before a real feature uses them.
10. Verify rendered behavior and update `docs/ux/DESIGN_SYSTEM.md` for durable system decisions.
