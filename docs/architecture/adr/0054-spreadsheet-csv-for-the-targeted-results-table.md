# ADR 0054 — Spreadsheet CSV for the targeted results table

Status: **Accepted**, with the owner's answers of 2026-10-28
([after-beta-1 plan](../../development/AFTER_BETA1_PLAN.md), sections 2 and
6.4). The Rust side is implemented: the closed word, the document and its
tests. No interface control offers it yet; the webview's control follows after
PR #164. The check in Excel, LibreOffice and WPS is the owner's and is
**pending**. Until it passes, no help, release or interface text claims
formula protection.
Related: [0047](0047-first-windows-beta-scope-and-implementation-route.md),
[0048](0048-stored-targeted-result-reuse-and-export.md) (section 5, the
results table);
the [M9 closure](../../product/M9_CLOSURE.md) and the beta-1
[release notes](../../release/beta-1/RELEASE_NOTES.md#csv-and-tsv-files).

## Context

ADR 0048 section 5 writes a stored targeted MS1 result as
`mscanvas_targeted_ms1_results` schema 1, in CSV or TSV, with every value
exactly as stored: UTF-8 without a byte-order mark and no change for
spreadsheets. That has two costs, which the beta-1 release notes state:

- A text value that begins with `=`, `+`, `-` or `@` may be evaluated as a
  formula when a spreadsheet opens the file. Target labels are typed by a
  person, and some text in the table is written by the engine.
- A spreadsheet that assumes the system's legacy code page, as some do when a
  `.csv` file is opened by double-click, shows non-ASCII labels garbled.

The M9 closure left the formula question to a release decision: keep the raw
text, add a separate export, or document it. The after-beta-1 plan keeps
"in-place spreadsheet-formula neutralization" refused (section 7.6), because
altering the CSV would change, without saying so, the text a scientific
document claims to hold.

On 2026-10-28 the owner selected an opt-in spreadsheet CSV and answered its
three open questions: `formula` is not a declared field; a trigger after a `;`
inside a declared field is neutralized too; and help and release text claim
formula protection only after a check in Excel, LibreOffice and WPS. The
interface name is "spreadsheet CSV" / "电子表格 CSV", and it is CSV only.

## Decisions

### 1. A third closed export word, beside the unchanged CSV and TSV

`export_targeted_ms1_table` accepts a third `format` word, `spreadsheetCsv`
(`TableFormat::SpreadsheetCsv`). Any other word is still refused with
`targeted_export_format_unknown`, and no new error kind is added. A saved
export answers `format: "spreadsheetCsv"`.

- **CSV and TSV do not change.** Their bytes are pinned by
  `fixtures/targeted-table-golden/results.csv` and `results.tsv`, which were
  committed before the variant existed and are not regenerated by it.
- **The save dialog:** title `Export targeted MS1 results`, filter
  `Spreadsheet CSV (*.csv)`, extension `csv`. The suggested name is
  `mscanvas-targeted-ms1-<artifact8>-results-spreadsheet.csv`, so it does not
  look like the plain CSV.
- **Everything else is the existing export:** the same output lane, the same
  refusals decided before the dialog opens, and the same named write that never
  replaces a file.
- **CSV only.** There is no spreadsheet TSV.

### 2. The document: `mscanvas_targeted_ms1_results_spreadsheet`, schema 1

- The file starts with one UTF-8 byte-order mark (`EF BB BF`), so a spreadsheet
  that opens it by double-click reads it as UTF-8.
- `#format` is `mscanvas_targeted_ms1_results_spreadsheet` and
  `#schema_version` is `1`. It is a format of its own and versions on its own:
  a reader can tell from the first line that the text was changed for
  spreadsheets.
- Otherwise it is the CSV: the same preamble keys in the same order, the same
  40 columns, RFC 4180 quoting, `\n` line endings, and an empty cell, never
  zero, for an absent value.
- The byte-order mark comes before `#format`. A reader that skips lines
  starting with `#` must remove the mark first, or it reads the first preamble
  line as data. A reader that needs the stored text exactly reads the CSV.

### 3. Declared text fields

Only these fields are altered, and only in this variant:

| Field | Where | Whose text |
| --- | --- | --- |
| `label` | column | the user's |
| `adduct` | column | the engine's, from the stored row |
| `model_status` | column | the engine's, from the stored row |
| `engine_pyopenms`, `engine_openms`, `engine_openms_revision` | preamble | the engine's report about itself |

Nothing else is declared:

- **`formula`** (owner's answer). A stored formula is a plain neutral sum
  formula, so it starts with an upper-case element symbol and can never start a
  trigger.
- **Numbers**, including negative numbers and the plan values written as the
  plan records them. `-12.5` is a number to a spreadsheet, and a number written
  as text would stop being one.
- **Code-owned words and identifiers:** `target_id`, the outcome and failure
  words, `engine_intensity_source`, `true`/`false`, the `;`-separated target
  identifiers, the digests, the preamble keys and their fixed values. They come
  from closed vocabularies or from formats that cannot start a trigger.

The code holds the declared set as two constants, `SPREADSHEET_TEXT_COLUMNS`
and `SPREADSHEET_TEXT_PREAMBLE_KEYS` (`project/targeted_output.rs`). A test
asserts both exactly, so `formula` or any other field cannot join them
unnoticed.

### 4. The trigger rule

In a declared field, one apostrophe (`'`, U+0027) is inserted before a
**trigger character** that starts a cell. A cell starts at the first character
of the value and at the character immediately after a `;`, a line feed
(U+000A) or a carriage return in it; any double quotes (`"`) right at a cell
start are passed over, so the trigger after them is the one marked. The trigger
characters are:

`=`, `+`, `-`, `@`, tab (U+0009) and carriage return (U+000D).

Nothing is removed and nothing else changes. The apostrophe is added before CSV
quoting, so a quoted field reads `"'=SUM(1,2)"`, never `'"=SUM(1,2)"`. Examples:
`=SUM(1,2)` becomes `'=SUM(1,2)`; `+x;-y;@z;=w` becomes `'+x;'-y;'@z;'=w`;
`-1 (did not converge)` becomes `'-1 (did not converge)`; `a;"=1` becomes
`a;"'=1`; `ok` + line feed + `=1` becomes `ok` + line feed + `'=1`; `a;b`,
`a"=1` and `#hash` are unchanged.

The six characters are the set commonly documented for CSV formula injection.
The rule after `;` is the owner's: a spreadsheet that splits on `;` starts a
new cell there. To such a spreadsheet the CSV field's quotes are text, so a
line break inside a quoted field ends its record and the text after it starts
the next one, and a `"` at a cell start may be read as a quote around the
trigger.

These cases are **decided, not verified**. The owner's check covers them:

- whitespace before a trigger (a space, then `=1`) is not neutralized; CSV
  already quotes a field with a leading space;
- a space after the semicolon (`a; =1`) is not neutralized;
- full-width signs (`＝`, `＋`, `－`, `＠`) and other look-alikes are not
  triggers;
- a line feed is not itself a trigger, but the character after one starts a
  cell, so `=1` after a line feed is marked (a line feed reaches a declared
  field only through engine text: labels and engine versions refuse control
  characters);
- double quotes between the cell start and the trigger (`a;"=1`, `a;""=1`) are
  passed over and the trigger is marked; whether a spreadsheet would have
  evaluated it is not known, and a `"` that does not follow a cell start
  (`a"=1`) marks nothing;
- when a spreadsheet opens the file as CSV, it may show the apostrophe as part
  of the text (`'=SUM(1,2)`), not hide it.

### 5. No variant for spectrum and chromatogram data files

Spectrum and chromatogram data files hold only numbers and fixed ASCII words.
They have nothing to neutralize, so they get no variant.

### 6. No claim of protection before the check

Help and release text claim formula protection only after a check in Excel,
LibreOffice and WPS. That check is the owner's and is pending. Until it passes:

- the beta-1 release notes' "CSV and TSV files" section stays as written;
- no help, release or interface text calls the variant safe or protected.

## Alternatives considered

- **Neutralize the plain CSV in place.** Refused (plan section 7.6, ADR 0048
  section 5): the document that claims to hold the stored text would silently
  hold something else.
- **A spreadsheet TSV as well.** Not selected; the owner chose CSV only.
- **An `.xlsx` writer.** It would need a new dependency, and the dependency
  policy refuses one for this.
- **Quote every text field.** Spreadsheets evaluate a quoted field too, so it
  changes nothing.
- **Prefix every declared field, not only those with a trigger.** It would
  change values that need no change.
- **A leading space or tab instead of an apostrophe.** A spreadsheet may trim
  either one, and a tab is itself a trigger. The apostrophe is the mark
  spreadsheets already treat as "this is text".
- **Remove the trigger characters.** It destroys data.
- **Neutralize numbers too.** A negative number would become text.

## Consequences

- There are three documents. CSV and TSV keep the stored text exactly, and ADR
  0048 section 5 holds for them unchanged, including "UTF-8 without a BOM". The
  spreadsheet CSV names its changes in its format identifier.
- A label read back from the spreadsheet CSV can differ from the stored label
  by an apostrophe. A tool that compares labels reads the CSV.
- The mark cannot be undone. A value that already starts a cell with an
  apostrophe is written as it is, so the stored labels `'=x` and `=x` are both
  written `'=x`: two different labels of one plan can print the same. Only the
  CSV or `target_id` tells them apart.
- Until the webview adds `spreadsheetCsv` to `TargetedTableFormat`
  (`projectApi.ts`) and offers a control, after PR #164, the variant is reached
  only through the command.
- The golden fixtures in `fixtures/targeted-table-golden/` pin all three
  documents. The spreadsheet fixture holds the text after the byte-order mark;
  the test asserts the mark separately.

## What this amends

- **ADR 0048 section 5:** adds a third document beside the CSV and TSV, whose
  rules are unchanged. Section 4's suggested names gain
  `mscanvas-targeted-ms1-<artifact8>-results-spreadsheet.csv`.
